Exact facts. Flexible language.

WHAT GETS SEARCHED?

FeaturesStandard equipment described on the vehicle.

OptionsAdd-ons and packages listed for that vehicle.

The feature/option embedding represents this equipment text, so a customer’s phrase can be compared with descriptions that use different words.

Similar meaning can survive different wording.

An embedding is a numerical representation of meaning. It helps retrieve relevant descriptions without requiring the same words.

Why customer language is tricky

“Sunroog.” “Sunroof.”
“Moonroof.”

A typo, a familiar term, and a related equipment term can all point toward a roof-feature request. The agent interprets that intent; semantic retrieval helps when the inventory describes it differently.

04 / Engineering decisions

Built for real conversations.

Expand only what you want to explore.

01 / SEARCH RELEVANCEMatch intent to actual inventory.+

Make/model/year queries use normalized field filters. Known equipment can use direct fields, too. Messy feature descriptions and package names use feature/option embeddings; mixed requests keep their exact constraints while ranking semantic matches. Independent semantic searches can run in parallel and meet at the vehicle ID.

ElasticsearchSemantic searchAsync Python
02 / AGENT DESIGNGive each layer a focused job.+

Vehicle Enquiry handles conversational context and response generation. Inventory Expert uses a ReAct loop with five tools: normalize entities, search inventory, combine attribute searches, check availability, and inspect vehicle details.

ReActTool callingStructured responses
03 / CORRECTNESSKeep important constraints intact.+

Request-scoped context keeps dealer identity isolated during concurrent searches. Model–trim pairing avoids invalid combinations, and code preserves required test-drive eligibility across retries. Tool results apply pricing disclosure rules before reaching the model.

ContextVarsFilter enforcementData preparation
04 / FAILURE HANDLINGMake uncertainty visible.+

Availability-service failures are reported as errors rather than empty stock. Selected failures have bounded retries. Prompt-guided broadening can relax secondary search criteria, and the vehicle layer can signal the supervisor when a person needs to help.

MCPError reportingObservability
